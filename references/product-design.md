# Product design for a reliable business assistant

- Let users ask naturally; normalize the question internally.
- Retrieve internal knowledge first and search approved external sources only when evidence is insufficient.
- Ask only for missing facts that materially change the answer.
- Answer supported general rules before exceptions; do not suppress a correct main answer because a rare exception is unknown.
- Prefer newer applicable rules when dates and scope are explicit; disclose unresolved conflicts.
- Never turn assumptions into business facts.
- Keep answers conclusion-first and format complexity proportionally.
- Use long-term memory only for stable, user-authorized attributes. Do not memorize disputed corrections as authoritative knowledge.
- Knowledge improvement needs provenance and appropriate review; memory is not a substitute for governed source documents.
- Test empty retrieval, conflicting versions, malformed model output, unavailable tools, exhausted quota, incomplete cases, and first-use clarity.
